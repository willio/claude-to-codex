# Claude Web integration

This fork targets Claude Web as the planning and review surface while Codex remains the only component that mutates the local workspace.

## Architecture

Claude connects to the local Workspace Bridge as a remote MCP server. Because Claude's connector requests originate from Anthropic's cloud, the bridge must be exposed on a public HTTPS URL; the existing Cloudflare tunnel remains the transport.

The MCP surface stays read-only. Claude can inspect workspace metadata, files, search results, git status/diffs, and Codex execution summaries. It cannot run shell commands, edit files, or write git state through MCP.

## Setup

1. Run `c2c setup` in the workspace.
2. Copy the generated public `/mcp` URL and pairing code.
3. In Claude Web, open **Customize > Connectors**.
4. Click **+**, choose **Add custom connector**, and enter the generated MCP URL.
5. Claude performs OAuth discovery and dynamic client registration against the bridge.
6. On the bridge authorization page, enter the pairing code generated by Codex.
7. Enable the connector for the conversation from the `+` menu when needed.

The bridge supports authorization-code OAuth with PKCE, dynamic client registration, refresh tokens, revocation, protected-resource discovery, and scoped bearer tokens. No Claude API key is required.

## Connector lifecycle

Quick Cloudflare tunnel URLs can change after the tunnel is reclaimed. If the MCP URL changes, remove the old custom connector in Claude and add it again with the new URL. `c2c doctor` detects reclaimed endpoints and generates a fresh pairing code.

Named Cloudflare tunnels avoid this churn and remain the preferred persistent configuration.

## Security boundary

Claude is a reader, planner, and reviewer. Codex is the executor.

The bridge deliberately exposes no general command-execution or file-write tool. Existing sensitive-file denials, workspace-root confinement, OAuth scopes, pairing expiry, and git/read-only boundaries remain in force.

Workspace content is treated as untrusted project data, not as instructions to Claude.

## Current migration status

The Claude connector endpoint, product identity, package metadata, connector naming, and endpoint-repair behavior are migrated in the first slice. Some legacy internal identifiers and CLI/Skill copy still use `ChatGPT` names for backward compatibility; these are implementation labels rather than connector destinations and will be normalized in the next slice without changing persisted endpoint data.
